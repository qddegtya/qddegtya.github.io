{%- comment -%} ---------- RELATED: reuses the home .c-card system (+ placeholder) ---------- True relatedness, NOT Jekyll's site.related_posts (which without --lsi is just "the latest N posts", identical on every page). Candidate pool = the doc's own collection (site.posts for blog). Three ranked passes, most-specific first: 1. shares a tag (same topic - the strongest signal) 2. shares the category (same broad section - weaker) 3. recency top-up (same collection, newest, so the strip is never empty) Each pass appends by date-desc; concatenation preserves pass order, so tag matches always outrank category matches, which outrank filler. Dedupe across passes, take 3. Pure Liquid, no dependency. Robust to every front-matter form this content uses now or might later: - tags as a YAML array [a, b] OR a space string "a b" OR a comma string "a, b" (or mixed). Normalised by: join spaces (array -> string, no-op on a string) | replace commas with spaces | split on spaces | reject the empty tokens that double-spaces leave behind. Result: a clean token list regardless of the authored form. - the section field as singular `category` OR plural `categories` (array). Concatenated then normalised the same way, so either form is matched. Tokens are lowercased (downcase) before comparison, so "Python" and "python" count as the same tag. The normalisation is applied identically to the current doc and to each candidate, so two docs match if their cleaned, case-folded token sets intersect. {%- endcomment -%} {% if page.id and
